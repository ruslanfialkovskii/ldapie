# Repository Guidelines

## Project Structure & Module Organization
- `src/ldapie/` contains the core Python package and CLI implementation.
- `tests/` holds the pytest suite; shared mock-LDAP fixtures live in `tests/conftest.py`.
- `src/ldapie/demo/` holds the automated demo and its mock LDAP server (`ldapie --demo`).
- Shell completion is generated by Click at runtime (`ldapie --install-completion`); there are no checked-in completion scripts.
- Release and automation helpers are in `scripts/` (for example `scripts/bump_version.py`).
- Build metadata and tool config live in `pyproject.toml` (single source, including ruff and coverage), `mypy.ini`, `uv.lock` and the `Makefile`; `mise.toml` only provides the toolchain and aliases for the `make` targets.

## Build, Test, and Development Commands
- `make setup` (`uv sync --frozen --extra dev`) creates `.venv` from `uv.lock` with the package and the dev tools; `pip install -e '.[dev]'` is the unlocked fallback.
- `make test` or `pytest tests/` runs the test suite; `make cov` adds coverage (threshold 75%).
- `make demo` runs the mock LDAP demo.
- `make lint` runs ruff; `make format` sorts imports and formats with ruff; `make format-check` is what CI runs.
- `make typecheck` runs mypy using `mypy.ini`.
- `make audit` checks the locked dependencies for known vulnerabilities.
- After changing dependencies in `pyproject.toml`, run `make lock` (`uv lock --no-config`, so a user-level uv config never leaks into the lockfile) and commit `uv.lock`. CI runs the same `make` targets through `uv run --locked`.

## Coding Style & Naming Conventions
- Follow PEP 8 with project overrides in `pyproject.toml` (`[tool.ruff]`, line length 88, Python 3.10).
- Use 4-space indentation and UTF-8 files.
- Format and lint with ruff; keep type hints mypy-clean.
- Use snake_case for modules/functions and CamelCase for classes; keep CLI options in kebab-case.

## Testing Guidelines
- Tests live in `tests/` and follow `test_*.py` naming.
- Add coverage for new features and bug fixes where practical.
- Directory data is untrusted: anything printed from server values goes through `output.sanitize_text` and Rich's `escape`.

## Commit & Pull Request Guidelines
- Commit messages are short, imperative, and often include PR numbers (for example “Add type checking support with mypy (#17)”).
- Version bumps are committed explicitly (for example “Bump version to 0.1.4”).
- PRs should include a clear description, testing notes, and any new CLI behaviors or flags.
- If changes affect the UX, include screenshots or a terminal capture.

## Security & Configuration Tips
- Avoid committing credentials; use environment variables or `.env` where needed.
- `./.ldapie.yaml` may come from a cloned repository: it can only set `theme` and turn `use_ssl`/`starttls` on (see `config.py`). Keep it that way.
- GitHub Actions are pinned to commit SHAs and Docker base images to digests; Dependabot proposes updates.
- For SSL/TLS, document required certificates and test with the demo server before release.
